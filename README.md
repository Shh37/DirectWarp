# DirectWarp
DirectWarpは、Google/Bingの検索ページでトリガーを検知し、Custom Search JSON APIの検索候補とGeminiのURL予測・候補選定を使って転送先を決めるブラウザ拡張機能です。Gemini APIキーに加え、利用資格のあるCustom SearchのAPIキーとCX（検索エンジンID）が必要です。検索結果のスクレイピングには依存しません。

**現在の検索機能はCustom Search JSON APIの既存顧客向けです。新規顧客の受付は終了しており、既存顧客向けの提供も2027年1月1日に終了します。** 新規登録やキー・CXの作成だけで導入できるものではありません。[利用条件と料金](#custom-search-の利用条件と料金)を確認してください。トリガーを付けない通常検索は引き続き利用できます。

## 🌟 特徴

- カスタマイズ可能なトリガー文字列（デフォルト: `/d`）
- GoogleとBingの検索エンジンに対応
- ダーク/ライトテーマ対応
- 軽量で高速な動作
- オープンソース（MITライセンス）

## 🚀 インストール方法

### 開発モードでインストール

1. リポジトリをクローンします:
   ```bash
   git clone https://github.com/yourusername/DirectWarp.git
   cd DirectWarp
   ```

2. 依存関係をインストールします:
   ```bash
   npm install
   ```

3. 拡張機能をビルドします:
   ```bash
   npm run build
   ```

4. ブラウザに拡張機能を読み込みます:
   - **Chrome**の場合:
     1. `chrome://extensions/` を開く
     2. 右上の「デベロッパーモード」を有効にする
     3. 「パッケージ化されていない拡張機能を読み込む」をクリック
     4. `.output/chrome-mv3` フォルダを選択

   - **Firefox**の場合:
     1. `about:debugging#/runtime/this-firefox` を開く
     2. 「一時的なアドオンを読み込む」をクリック
     3. `.output/firefox-mv2` フォルダ内の `manifest.json` を選択

## 🎮 使い方

1. 検索エンジン（GoogleまたはBing）で検索します
2. 検索クエリの先頭にトリガー文字（デフォルトでは `/d`）を付けます
   - 例: `/d 天気`
3. 検索を実行すると、最も関連性の高い検索結果に自動でリダイレクトされます

## ⚙️ 設定

拡張機能のアイコンをクリックして設定画面を開き、以下の設定をカスタマイズできます:

- **トリガー文字列**: デフォルトは `/d`
- **検索プロバイダー**: 新規設定は「未設定（通常検索を使用）」。利用資格がある既存顧客はCustom Searchを明示的に選択します。
- **モデル**: 既定は `gemini-3.5-flash-lite`。`gemini-2.5-flash` は過去に利用したユーザー向けに保持します（下記参照）。
- **候補数 N**: Custom Searchから取得する検索候補数（1〜10）
- **タイムアウト(ms)**: URL解決全体の待機期限（既定15秒、保存値は1,000〜120,000ms、設定画面は1〜30秒）
- **確信度しきい値**: リダイレクトを許可する最小スコア（0.0〜1.0、デフォルト 0.5）
- **テーマ**: システム設定に従う / ライト / ダーク
- **Gemini APIキー**: 端末内の拡張機能ストレージに保存し、認証ヘッダーで送信します。暗号化された秘密保管庫ではありません。
- **Custom Search APIキー・CX**: 既存顧客の検索に必要。入力済みでも利用資格を確認したことにはなりません。

現在の処理は、Custom Searchによる候補取得とGeminiによるURL予測を並行して開始します。検索に失敗した場合や有効な候補が0件の場合は通常検索へ戻ります。予測の確信度がしきい値以上なら候補と照合し、一致した候補URLだけを採用します。それ以外は取得候補をGeminiに渡して選定し、同じ候補照合を行います。検索サービスの比較・移行は[Issue #6](https://github.com/Shh37/DirectWarp/issues/6)以降で扱います。

### 検索プロバイダーの共通契約と設定移行

backgroundは `lib/search` のプロバイダー準備と検索契約だけを利用します。Custom Search固有のキー・CXの読込、リクエストとJSONの変換はアダプター側に閉じています。新サービスのクライアントや本番切替は含めません。

- 入力: トリガー除去後の `query`、`count`（整数1〜10）、URL解決全体で共有する `deadlineAt`（Unixミリ秒）と `AbortSignal`。
- 成功: `{ ok: true, candidates: [{ url, title?, snippet? }] }`。0件は空配列で返し、backgroundが通常検索へ復帰します。URLは共通検証を通したhttp/httpsのみです。
- 失敗: `{ ok: false, error: { kind, message } }`。`kind` は未設定、未対応プロバイダー、不正入力、認証・権限、利用上限、サービス利用不可、通信、期限切れ、中断、応答形式不正を区別します。生の例外・HTTP本文・資格情報は共通エラーに含めません。

Custom SearchのHTTPステータスは400を不正入力、401/403を認証・権限、429を利用上限、その他をサービス利用不可へ対応付けます。403には割り当て等の理由もあり得るため、この分類だけで個別の原因が確定したとは扱いません。キー読込、通信、本文読込も元の期限に含め、アダプターが停止しなくてもbackground側の期限で復帰します。再試行・ページ追加・別サービスへの自動送信は行いません。

保存済みの設定オブジェクトに `searchProvider` がない旧版だけは、読込時に `custom-search` として扱います。読込だけでは保存せず、繰り返し読込・保存しても既存の検索キー・CXは保持します。設定自体がない新規ユーザーは `none`（未設定）です。未知の文字列や不正な保存値はCustom Searchへ置き換えず、検索を止めて設定画面での選び直しを案内します。プロバイダーを変更しても保存済みキー・CXを削除しません。

公式の入出力仕様の確認日時: **2026年10月29日 19:52 JST**。[Custom SearchのREST利用方法](https://developers.google.com/custom-search/v1/using_rest)、[cse.listの引数・応答](https://developers.google.com/custom-search/v1/reference/rest/v1/cse/list)。後続アダプターの追加は[Issue #8](https://github.com/Shh37/DirectWarp/issues/8)で、採用とキー・データ取扱いの判断は[Issue #6の調査結果](https://github.com/Shh37/DirectWarp/issues/6#issuecomment-6494715759)に残しています。

### 転送URLの検証

予測・通常選定とも、採用するURLは検索候補の文字列との**完全一致**を必須とします。候補ID方式ではなく完全一致を選び、現在のURL応答形式と候補なしの並行予測を維持します。ドメインだけ・前方一致・部分一致では判定せず、パス・ポート・クエリ・フラグメントも比較します。大文字小文字や末尾スラッシュなど同等に見える別表記も、推測で同一視せず拒否します。候補IDだけの応答は受け付けません。

検索候補・モデル応答・最終転送先を共通関数で `new URL()` により解析し、ホストのあるhttp/httpsだけを許可します。userinfo（空の`@`を含む）、空白・制御文字・バックスラッシュ、壊れたパーセント符号化は拒否します。検索タイトルやsnippetに別URLへの指示が含まれていても、アプリ側の候補一覧は変更されません。採用対象の結果が候補外・不正・低確信度なら通常検索へ戻ります。予測通信自体の失敗時には、全体期限内で通常選定を試みます。ただし入力・認証・権限・請求・モデル不在・利用枠の恒常エラーでは通常選定も送信しません。

confidenceはモデルの自己申告であり、成功確率の保証ではありません。候補所属とURL構文の確認は、URLの存在・内容の安全性・移動後のリダイレクト先を保証しません。存在確認のための追加アクセスは行いません。

公式資料確認: **2026年10月29日 19:43 JST**。[Geminiの構造化出力と値の検証](https://ai.google.dev/gemini-api/docs/structured-output)、[WHATWG URL仕様](https://url.spec.whatwg.org/)。

### Geminiの構造化応答と再試行

予測・候補選定・汎用関数は同じ `generateContent` REST処理を使い、`generationConfig.responseFormat.text` に `mimeType: APPLICATION_JSON` とJSON Schemaを指定します。許可モデル2種は公式に構造化出力対応ですが、実APIでの組合せ検証は行っていません。SDKやInteractions APIは使用しません。

先頭の応答候補だけを対象にし、`finishReason: STOP` を必須にします。その候補内の思考ではないtext partを順番に連結してJSON解析し、ブロック・出力上限・未完了・候補なし・回答なし・不正JSON・型不正を区別します。別候補をつなげたり、説明文から波括弧だけを抜き出して採用したりしません。confidenceは有限のnumberかつ0〜1に限定し、`true`、`null`、文字列は拒否します。構造化出力に加えて候補URLへの完全一致検証を行います。

400/401/402/403/404、501などの恒常エラーは再試行しません。408/500/502/503/504と、一時制限と判断できる429だけを最大2回再試行します。待機は1秒・2秒に最大249msのjitterを加え、`Retry-After` とGoogle RPC `RetryInfo` が指定する待機のうち長い方を尊重します。元の期限までに待機できない場合は打ち切ります。待機中のキャンセルもタイマーを解除します。再試行により送信回数が増える場合があり、サーバー処理や課金の取消しは保証しません。

429は `QuotaFailure` のquotaId/metricが分・秒単位と識別でき、ゼロ枠・日次枠ではない場合、またはquota詳細なしで有効な `RetryInfo` がある場合だけ再試行します。未知の枠、日次枠、ゼロ枠、情報不足は再試行せず利用枠の確認を案内します。これは短いURL解決期限に合わせた保守的な判定で、全ての割当エラーを確定診断するものではありません。生のAPI本文、キー付きURL、元例外を表示用エラーやログに含めません。

公式資料確認: **2026年10月29日 20:07〜20:09 JST**。[generateContent REST仕様](https://ai.google.dev/api/generate-content)、[構造化出力](https://ai.google.dev/gemini-api/docs/structured-output)、[3.5 Flash-Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)、[2.5 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash)、[再試行指針](https://ai.google.dev/gemini-api/docs/troubleshooting)、[割当](https://ai.google.dev/gemini-api/docs/rate-limits)、[Google RPCのエラー詳細](https://github.com/googleapis/googleapis/blob/master/google/rpc/error_details.proto)。

### Geminiキーとリクエスト保存の方針

公式資料確認: **2026年10月29日 20:16〜20:17 JST**。

GeminiはAuth key、または明示的なAPI制限を持つStandard keyを使用します。無制限の旧Standard keyは拒否されます。2026年5月28日以降にAI Studioで作成するキーは、サービスアカウントに関連付けられたAuth keyが既定です。キー文字列の接頭辞・長さだけで種類や利用可否を判断せず、入力の非空確認と利用案内に留めます。GeminiとCustom Searchのキーは別の保存項目であり、共用を前提にしません。既存キーを自動変換・失効・削除することはありません。[公式のキー条件](https://ai.google.dev/gemini-api/docs/api-key)

全生成経路（予測・候補選定・汎用関数・再試行）は、キーを `x-goog-api-key` ヘッダーに入れ、URLクエリには含めません。検索語をGeminiへ送り、候補選定では候補URL・タイトル・要約も送ります。端末内のキー保存は外部データの保存方針とは別です。現在はユーザー自身のキーを拡張機能ストレージに保持する構成で、端末・拡張の権限を持つ人から秘密にする暗号化保管を保証しません。配布用の共通キーを同梱しません。

採用方針は**全Generate Contentリクエストで `store:false` を明示**することです。2026年10月26日以降の新規有料プロジェクトはリクエスト保存が既定で有効ですが、リクエスト指定がプロジェクト設定に優先します。ユーザーのクラウド設定は変更しません。[ログとリクエスト保存](https://ai.google.dev/gemini-api/docs/logs-datasets)、[RESTのstoreフィールド](https://ai.google.dev/api/generate-content)

`store:false` はAI Studioのリクエスト保存を制御するもので、無料サービスでのデータ利用や全種類の保持を無効にしません。無料サービスの入力・出力は製品改善や人手レビューに利用される場合があり、機密・個人情報は送らないでください。有料サービスでは製品改善に使わないとされますが、不正利用対策・法令対応等の一時保持は別です。EEA・スイス・英国等には適用条件の違いもあるため、プロジェクトの課金状態・地域と[データ利用条件](https://ai.google.dev/gemini-api/terms)を確認してください。拡張はこれらの利用資格をキー文字列や保存設定だけから判定しません。

### Gemini モデルと保存済み設定

公式資料の確認日時: **2026年10月29日 18:34 JST**。利用できるモデルIDは `lib/settings.ts` で明示し、`latest` や Preview に自動追従しません。全カタログを許可するのではなく、次の2モデルを対象にします。

| モデル | 用途と利用条件 |
| --- | --- |
| `gemini-3.5-flash-lite` | 新規設定・移行先の既定。公式に安定版でテキスト出力対応、新規プロジェクト向けに案内されています。 |
| `gemini-2.5-flash` | 既存設定を保持。過去に利用したユーザーだけにアクセスが制限されており、新規プロジェクト向けの既定にはしません。2.5 Pro / Flash-Lite は今回の許可対象には追加しません。 |

3.5 Flash-Lite は短いURL選定に用いるモデルとして、公式の低コスト・低遅延向けの位置づけと安定版提供を理由に採用します。Standard の料金は100万トークンあたり入力 **US$0.30**、出力（思考を含む）**US$2.50**。無料枠もありますが、割り当てや実際のアクセス権はプロジェクトに依存します。入力上限は1,048,576、出力上限は65,536トークンです。既存クライアントは `generateContent` に user テキストを送るだけで、非推奨のサンプリング指定や model ターンの事前入力は行っていません。

`gemini-2.0-flash` は2026年6月1日に提供終了。`gemini-2.0-pro` は今回確認した公式カタログに正式IDとして確認できないため許可しません。保存済みモデルが終了済み・不正・未設定の場合は、読込時に既定モデルを適用します。トリガー、候補数、タイムアウト、しきい値、テーマ、各キーはそのまま保持します。有効な保存モデルは変更しません。

読込だけではストレージを書き換えず、設定画面に移行通知を出します。「保存」で選択中のモデルを永続化し、通知を解除します。background が先に読み込んだ場合も通知は失われず、保存前後とも再読込でモデルが変わることはありません。

**実APIによる利用可否・品質・速度は未検証**です。モデルの利用条件と拡張全体の導入可否は別で、検索用APIキーとCXも必要です。この変更ではサービス登録、課金、実API呼び出しを行いません。

根拠: [モデルカタログ](https://ai.google.dev/gemini-api/docs/models)、[3.5 Flash-Lite の仕様](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)、[提供終了・アクセス制限](https://ai.google.dev/gemini-api/docs/deprecations)、[料金](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite)、[リリースノート](https://ai.google.dev/gemini-api/docs/changelog)、[移行時のAPI変更](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.6)。

### モデル一覧の確認・更新

設定画面の「保存済みキーでモデル一覧を確認」を押したときだけ、`models.list` を取得します。未保存のキーでは通信しません。モデル一覧取得は検索語や候補を送らず、生成の接続テストも行いません。モデル選択・既定値・保存設定は自動変更せず、確認できない場合も静的な対応モデル一覧を残します。

一覧はページサイズ1000を指定し、`nextPageToken` がなくなるまで同じ条件で取得します。重複は集約し、同一IDで対応メソッドが矛盾する場合は利用可と推測しません。通信・本文読込・ページ送りは15秒の共通期限で中断できます。循環するページトークンや20ページを超える応答は不完全として失敗にし、部分的な一覧を確認済みとして記録しません。権限・429・ネットワーク等の失敗時には自動再試行しません。

照合対象は `ALLOWED_MODELS` の明示的なIDだけです。APIの `supportedGenerationMethods` にある `generateContent` に加え、公式モデル別資料に基づく `MODEL_CAPABILITIES` のテキスト出力・構造化出力・安定版区分を確認します。Models APIの現行フィールドだけではこれらを全て判定できません。音声・画像・Embedding専用、Preview、未知のIDを取得しただけで選択可能にはしません。**一覧への掲載は生成の成功、割当、料金・アクセス条件の保証ではありません。**

最終確認日時（表示はJST）と成功/失敗を保存します。確認記録にはキー値やAPIの自由文を含めず、キーのSHA-256識別子と照合して別キー・別プロジェクトの結果を流用しません。キーを編集中・変更後は以前の結果を表示せず、確認中のキー変更や画面を閉じた場合は処理を中断します。同じキーのクラウド側権限・課金・利用条件の変更は自動検知できないため、変更後は明示的に再確認してください。

運用手順:

1. キー・プロジェクト変更後、またはモデルの終了・アクセス制限の告知時に、公式の[モデルカタログ](https://ai.google.dev/gemini-api/docs/models)と[提供終了一覧](https://ai.google.dev/gemini-api/docs/deprecations)を確認します。
2. 拡張の設定画面でキーを保存し、一覧確認を実行して日時・対象モデルの掲載とメソッド対応を確認します。生成APIを自動実行して利用枠を試しません。
3. 対応モデルを追加・削除するときは、モデル別の出力・構造化出力・安定版区分、料金・終了予定を公式資料で確認し、`ALLOWED_MODELS` / `MODEL_CAPABILITIES` / 表示名と保存設定の移行を同じPRで更新します。静的一覧の変更を自動採用しません。
4. fixture、型チェック、Chrome/Firefoxビルドで確認し、実APIで未確認の項目をPRに残します。

公式資料確認: **2026年10月29日 20:20〜20:21 JST**。[Models APIのページング・フィールド](https://ai.google.dev/api/models)、[提供終了](https://ai.google.dev/gemini-api/docs/deprecations)、[プロジェクト単位の割当](https://ai.google.dev/gemini-api/docs/rate-limits)。テキスト・構造化出力は同日に確認したモデル別資料を使用しています。実際の一覧APIは今回呼び出していません。

### タイムアウトと通常検索への復帰

URL解決を要求する時点で期限を決め、メッセージ配送、background の設定読込、Custom Search、Gemini の予測・候補選定、応答本文の読込まで同じ期限を共有します。予測には全体時間の60%までを使い、候補選定で待機時間を与え直しません。既存の保存済みタイムアウト値は変更しません。

期限切れ・通信失敗時はエラーを表示し、2秒後にトリガーを除いた通常検索へ戻ります。background から応答が来ない場合も content 側の監視で復帰します。「キャンセル」で直ちに通常検索へ戻れます。「設定を開く」を選んだ場合は自動復帰を止めます。画面離脱時には通信と復帰・ワープ用タイマーを解除し、期限後の遅延応答で再転送しません。

2026年10月29日 19:08〜19:09 JST に [Fetch仕様](https://fetch.spec.whatwg.org/#abort-fetch) と [AbortControllerの説明](https://developer.mozilla.org/en-US/docs/Web/API/AbortController/abort) を確認しました。クライアントの中断はサーバー側の処理停止や課金取消しを保証しません。
